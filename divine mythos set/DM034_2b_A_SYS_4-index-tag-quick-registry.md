## 5. V8 DESIGN PRINCIPLES (architecture, not narrative)

*Migrated into the Rev 6 architecture layer from DM034_1 on 2026-06-06;
originally DM003_0, then DM036. These are architecture principles
for the file system and project structure — not narrative rules.*

1. Match each rule to the cheapest storage layer that still guarantees enforcement.
2. A fully consistent corpus needs fewer rules because the pattern is the rule.
3. Rules in DM000 are a correction layer, not a teaching layer.
4. Every YAML kernel token is budgeted insurance, not waste.
5. More files, tighter files, atomic files — file count is not a cost. Every file
   that earns its own slot is one fewer collision hiding in a megafile.
6. Symbolic references survive renumbering, used as handles, not addresses.
7. A live module is one cluster on three logical layers—source control, atomized live state, and
   timeline narrative — and played turns are narrated as beats, never left to
   accrete in the state ledger. (See §6 and DM034_1 §1/§3.)
8. **A filename must never contradict the file's own frontmatter, and an
   archived file must be distinguishable from a live one by name alone.**
   Added Rev 8.5, 2026-08-23. The corpus's status token is the `_S_` infix
   recorded in the off-corpus history archive. A slot that disagrees with `segment_parent`, or an
   archived file whose name reads as live, is a defect - it puts the burden of
   correctness on the deep index, which is never resident.
9. **Never enumerate a set that grows during play.** Added Rev 8.5.2,
   2026-08-27. An index row listing a chain member-by-member is correct exactly
   until the next session, and it fails silently — the chain grows, the row does
   not, and nothing complains. State the ordering law and derive the members.
   The `_N` row cost three separate repairs before this principle existed; the
   fourth replaced it with a rule.

## 6. MODULE-CLUSTER FILENAME ROLES

A live D&D module run as ongoing play (TR3-SKT / Storm King's Thunder is the first)
is filed as one DM-number cluster whose role-suffixes are fixed. This is the naming
standard for every future module so the architecture stays predictable past T700.

Outside live-module clusters, `_D1`, `_D2`, and later `_D#` suffixes designate
atomic dossier children under one subject number. They load by direct ID and do
not imply source-control, live-state, or narrative-beat behavior.

**Suffix namespaces are scoped, and the scope must be known first.** A bare
suffix letter does not carry a single global meaning. There are four namespaces:

| Namespace | Applies to | Example |
|---|---|---|
| Module-cluster roles | a DM number running a live module | `DM038_CH` = prep change ledger |
| Dossier children `_D#` | any non-module subject number | `DM043_D1` = Kiyuru runtime dossier |
| Dossier letters `_A` ... `_E` | a paired-subject dossier set | `DM041_C` = Doran profile |
| Antagonist dossiers `_DS#` | champion-band antagonist subjects | `DM045_DS3` = Eclavdra |

`DM038_CH` and `DM041_C` are not in conflict; they are in different namespaces.
Read the DM number's kind before reading its suffix. Registered Rev 8.5.

| Suffix on the module's DM number | Role | Central write mode | Example |
|----------------------------------|------|--------------------|---------|
| `_1` … `_6` (source parts) | Adapted facts, maps, stat blocks, doctrine | canonical owner; never during play | active source owners only; completed Chapters 1–9 resolve through the archive inventory |
| `_CH` | Prep corrections, source-edit audit, approved simulation findings | `append-only-audit-history` | DM038_CH |
| `_L` | Sole current-story ledger—position, gates, route, readiness, durable regional state, and endgame fronts | `overwrite-after-confirmed-commit` | DM038_L |
| `_N#` | **Timeline narrative family. This file names the role; it never lists the members.** Membership is enumerated in the DM034_0 FILE TABLE and validated against disk by `tools/xref_checker.py` — see the family rule below. | `timeline-narrative-mirror-after-canon-or-play` | the `_N#` chain |

### The `_N#` family rule

`#RULE-N-FAMILY-BY-RULE`

`DM034_0` FILE TABLE owns the operative statement; this is its naming mirror and
carries no member list of its own.

- The checker keeps the DM034_0 FILE TABLE complete, but it cannot say which
  member is live. That is what this rule is for.
- Highest-numbered `_N#` on disk = **the open lane**, where the next played beat
  records.
- The one below it = **last closed prose**.
- Everything below that = closed history, retrieval only.
- Registered ordering exception: `_N3` is a shard of `_N1` (T533–T536) and sorts
  before `_N2`. This is the only exception; do not add another.
- Opening a lane edits no index. Create the file, set the predecessor's
  `successor_file`, update `DM034_0` CURRENT ARC. Nothing here changes.
